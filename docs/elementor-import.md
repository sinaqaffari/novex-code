# Elementor JSON import (initial local slice)

In the page editor choose **بررسی خروجی Elementor**, select an Elementor page/template JSON export, review the approximate preview and warnings, then explicitly confirm replacement. The file is parsed in the browser; no WordPress credentials, network asset fetch, or publication are involved. The result is a normal draft edit with the existing undo and autosave workflow. Keep the original export and, if needed, export the current Novex document before replacing it.

Supported: section, column and container nesting (legacy layout is approximate), heading, text-editor (plain text only), button, image placeholders, image-box converted approximately to an image placeholder with native heading and text, and icon-list converted approximately to native text and buttons (icons and semantic list markup are not retained). Only safe button links, basic text alignment, and exact supported pixel spacing steps are converted. Desktop, tablet and mobile spacing are mapped to the existing controlled style fields; custom Elementor breakpoints are not converted. In RTL, right/left padding maps to inline start/end. Native responsive CSS uses the current Novex breakpoints, not Elementor custom breakpoints.

Images are never fetched or linked automatically; reselect them from the media library. Unknown widgets become editable text placeholders. Dynamic content, embedded code, rich text formatting, arbitrary CSS, typography, colors, icons, forms, WordPress content and plugins are not migrated. Unsupported settings are reported by source ID; source metadata is not retained in the page schema. Reports are transient and should be reviewed before applying. The parser accepts at most 1 MiB, 200 nodes and 8 levels. Unsupported formats and malformed inputs fail before changing the page.

This Elementor converter is not a WordPress REST connection, an asset migration system, or full Elementor compatibility. Preview is the editor's approximate React preview, not proof of published visual fidelity. The existing Astro renderer remains the production renderer. No remote asset or plugin code is executed.
