# Local WordPress WXR import

In the builder, choose **بررسی خروجی WordPress WXR**, select a local WXR XML export (maximum 1 MiB and 200 items), choose a page or post, review the preview and warnings, and explicitly confirm replacement of the current page's nodes. The current title, slug and page theme are preserved. The result is an ordinary unsaved builder edit, subject to the existing autosave, undo and conflict workflow; it is never published automatically.

The importer reads WXR page/post titles, source IDs, slugs, status, excerpt and content for inspection. Content is converted approximately into editable native headings, plain text, safe standalone short links as buttons, and image placeholders. Inline hyperlinks, formatting, list semantics, WordPress blocks, categories, metadata, excerpts and attachments are not persisted; HTML is never rendered directly. Long headings are split into text, H5/H6 become H4, and source images must be reselected. Posts become builder page content, not blog posts. Images and remote assets are never downloaded. Unsupported records (e.g. attachments) are counted. The original export is not stored: keep a backup.

XML DTD and entity declarations are rejected and the parser is limited to 1 MiB, 20,000 XML tags, 64 levels and 200 items. It does not execute source HTML, JavaScript or PHP. This is not a complete WordPress migration, REST connection, WXR asset migration, or comprehensive WordPress migration; preview uses the editor renderer and needs browser verification.

## Bulk draft creation

For exports with 1–20 inspected pages/posts, the same dialog can create all of them as separate builder drafts. Enter a valid unique prefix, review warnings, and confirm the explicit creation prompt. The resulting slugs are `<prefix>-1`, `<prefix>-2`, etc.; titles come from the source. Contents use the same approximate structured conversion, and WordPress posts become builder pages. The authorized server validates every document and writes all pages in one queued store operation; any slug collision rejects the entire batch without overwriting anything. No pages are published. More than 20 items cannot be bulk-created with this flow; single-item import remains available for the 200-item inspection limit. This is not an asset, category, or WordPress post migration, and file-store locking is only in-process.
