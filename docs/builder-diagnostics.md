# Builder pre-publication checks

The editor's «بررسی صفحه» sends the current in-memory snapshot (including unsaved changes) to a permission-protected diagnostic endpoint. The endpoint validates the normal v1 document, checks bounded local media references, and returns advisory issues. It does not save, publish, fetch external URLs, or inspect arbitrary filesystem paths. Users can select a reported node in the editor. A changed document is marked stale and can be checked again.

Checks cover missing page description, empty page, empty headings, extra H1 (the published page title is already H1), image placeholders, missing alt text, missing simple media-library references, unverified external images, placeholder button links, and nodes hidden at all three breakpoints. Empty alt text can be appropriate for a decorative image, so this is a review prompt, not an accessibility failure. Asset checks only apply to `media://` and simple `/media/` references; arbitrary internal URLs and external availability are not checked. The result is not a complete accessibility, SEO, security, or broken-link audit. Existing publication behavior and API remain unchanged; warnings never block publication, including direct API publication. File availability can change after a report.
