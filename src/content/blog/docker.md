این مخزن با سرویس `app` در `docker-compose.yml` اجرا می‌شود. برای اجرای پایه، سرویس پایگاه‌دادهٔ جداگانه‌ای تعریف نشده است؛ تنظیمات، کاربران و داده‌های فروشگاه در فایل‌های داخل `data/` نگه‌داری می‌شوند. فروشگاه از فایل JSON استفاده می‌کند و نوشتن‌ها را فقط در همان پروسه صف‌بندی می‌کند؛ این چیدمان برای اجرای چند نمونهٔ هم‌زمان، پایگاه‌دادهٔ مشترک فراهم نمی‌کند.

## اجرا در محیط محلی

Docker Engine یا Docker Desktop و Docker Compose باید نصب و در دسترس باشند. فرمان‌ها را از ریشهٔ مخزن اجرا کنید:

```sh
cp .env.example .env
docker compose up --build -d
docker compose ps
```

پس از کپی، فایل `.env` را پیش از راه‌اندازی باز کنید. نام کاربری و گذرواژهٔ نمونه برای توسعه‌اند؛ برای سرور عمومی مقدارهای امن خودتان را بگذارید. همچنین `CMS_SESSION_SECRET` را با یک مقدار تصادفی خصوصی و `SITE_URL` را با نشانی عمومی واقعی تنظیم کنید. اگر سایت پشت HTTPS است، `CMS_COOKIE_SECURE` را نیز فعال کنید.

وقتی وضعیت سرویس در خروجی `docker compose ps` سالم شد، سایت در `http://localhost:4321` و پنل در `http://localhost:4321/cms` در دسترس‌اند. برای دیدن گزارش‌های زنده از این فرمان استفاده کنید:

```sh
docker compose logs -f app
```

## فایل Compose چه چیزی را نگه می‌دارد؟

سه volume نام‌دار در `docker-compose.yml` به این مسیرها وصل شده‌اند:

- `novex-data` به `/app/data` — تنظیمات سایت، حساب‌های پنل، وضعیت افزونه‌ها و داده‌های فروشگاه.
- `novex-blog` به `/app/src/content/blog` — نوشته‌های Markdown.
- `novex-uploads` به `/app/src/assets/uploads` — تصویرهای بارگذاری‌شده.

برای نگه‌داشتن داده‌ها، پیش از تغییر نام یا حذف volumeها از هر سه نسخهٔ پشتیبان تهیه کنید. نوشته‌های مجله و تصویرها داخل volumeهای جدا از فایل‌های برنامه قرار دارند.

## پیش از انتشار عمومی

مقدارهای پیش‌فرض مدیر در نمونهٔ محیطی برای توسعه‌اند؛ آن‌ها را روی سرور عمومی استفاده نکنید. کلیدهای افزونهٔ پرداخت یا پیامک فقط وقتی کاربرد دارند که افزونهٔ مربوط نصب و پیکربندی شده باشد. مقدارهای محرمانه را از متغیرهای محیطی یا سامانهٔ مدیریت رازها تزریق کنید و در Git قرار ندهید. این Compose یک سرویس برنامه تعریف می‌کند؛ فروشگاه فایل‌محور را به چند نمونهٔ هم‌زمان مقیاس ندهید.
