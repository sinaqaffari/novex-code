افزونه در این پروژه یک ماژول TypeScript از پیش شناخته‌شده در مخزن است. فایل `plugin.json` شناسه، نسخهٔ API، قابلیت‌ها، قلاب‌ها، تنظیمات و مسیرهای اعلام‌شده را توصیف می‌کند؛ پیاده‌سازی در زمان build باندل می‌شود و هنگام نیاز بارگذاری می‌شود. این قرارداد الهام‌گرفته از الگوهای افزونه‌ای است، نه سازگاری با افزونه‌های PHP وردپرس.

## مسیرهای API محدود و مشخص‌اند

مسیر هر افزونه باید در مانیفست ثبت شود؛ handler نمی‌تواند مسیر دلخواه یا endpoint عمومی تازه‌ای بسازد. مسیرهای `public` فقط GET می‌پذیرند و به قابلیت `api:public` نیاز دارند. مسیرهای `cms` زیر `/cms/api/plugins/<id>/<path>` قرار می‌گیرند و پشت نشست مدیر، کنترل مجوز سمت سرور و حفاظت CSRF برای POST هستند. POST فقط JSON با اندازهٔ محدود می‌پذیرد؛ handler دادهٔ parseشده می‌گیرد، نه cookie یا header خام.

## قابلیت به‌معنای sandbox نیست

قابلیت‌ها دسترسی افزونه را در API میزبان محدود می‌کنند، اما کد افزونهٔ مورد اعتماد در همان پردازهٔ Node اجرا می‌شود. این پروژه PHP را اجرا نمی‌کند، نصب بسته یا ZIP از پنل ندارد، امضای بسته را بررسی نمی‌کند و sandbox کد شخص ثالث نیست. بنابراین اضافه‌کردن افزونه باید مانند تغییر کد برنامه بازبینی شود.

قلاب‌ها نیز برای هر نوع رفتار، سیاست خطای صریح دارند: خطای بعضی قلاب‌های نمایش جدا می‌شود تا خروجی میزبان بماند؛ خطای قلاب پرداخت fail-closed است و نباید به موفقیت تبدیل شود. مقدار رازها در مانیفست ذخیره نمی‌شود و از متغیرهای محیطی یا سامانهٔ مدیریت رازها می‌آید.

## پیش از افزودن افزونه

بررسی کنید که مسیرها و capabilityها کمینه باشند، ورودی و خروجی محدود و اعتبارسنجی شوند، مجوز CMS سمت سرور اعمال شود و خطاهای پرداخت fail-closed بمانند. این قرارداد از افزونه‌های داخلی پشتیبانی می‌کند؛ به‌تنهایی جایگزین بررسی امنیتی یا sandbox برای کد نامطمئن نیست.
